## 49. Java 11 Interview Questions

Java 11 is **LTS** — common in production. Key features for interviews.

# 2. New String methods?

<details>
<summary>Show Answer</summary>

**Answer:**

Java 11 added: `isBlank()`, `lines()`, `repeat(int)`, `strip()`, `stripLeading()`, `stripTrailing()`.

```java
"  ".isBlank();        // true
"ab".repeat(3);        // "ababab"
"  hi  ".strip();      // "hi" — Unicode whitespace aware
"a\nb\c".lines().count(); // 3
```

**Interview Point:** strip() = Unicode-aware trim. isBlank() checks empty or whitespace only.

</details>

---

# 3. isBlank()?

<details>
<summary>Show Answer</summary>

**Answer:**

`isBlank()` returns **true** if string is empty **or** contains only whitespace (space, tab, newline).

```java
"".isBlank();      // true
"   ".isBlank();   // true
"\t\n".isBlank();  // true
"hi".isBlank();    // false
```

vs `isEmpty()` — only true for length 0, not whitespace.

**Interview Point:** isBlank = empty or whitespace. isEmpty = length 0 only.

</details>

---

# 4. lines()?

<details>
<summary>Show Answer</summary>

**Answer:**

`lines()` returns a **Stream of lines** — splits on `\n`, `\r`, or `\r\n`.

```java
String text = "line1\nline2\nline3";
text.lines()
    .filter(line -> !line.isBlank())
    .forEach(System.out::println);
```

Lazy stream — good for large text files without splitting entire string to array.

**Interview Point:** lines() → Stream<String>. Split by line terminators. Use with Stream API.

</details>

---

# 5. repeat()?

<details>
<summary>Show Answer</summary>

**Answer:**

`repeat(int count)` returns string repeated **count** times.

```java
"ab".repeat(3);  // "ababab"
"-".repeat(50);  // separator line
```

`count` must be ≥ 0. `repeat(0)` returns empty string.

**Interview Point:** repeat(n) — simple string repetition. Replaces manual loops.

</details>

---

# 6. strip()?

<details>
<summary>Show Answer</summary>

**Answer:**

`strip()` removes **leading and trailing whitespace** — Unicode-aware (unlike `trim()` which is ASCII-limited).

```java
"\u2005hello\u2005".strip();  // works on Unicode spaces
"  hi  ".strip();              // "hi"
```

Also: `stripLeading()`, `stripTrailing()`.

**Interview Point:** strip() > trim() for Unicode whitespace. Java 11 preferred over trim().

</details>

## HTTP Client

---

# 7. New HttpClient API?

<details>
<summary>Show Answer</summary>

**Answer:**

Java 11 `java.net.http.HttpClient` — modern async/sync HTTP client replacing `HttpURLConnection`.

```java
HttpClient client = HttpClient.newHttpClient();

HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Authorization", "Bearer token")
    .GET()
    .build();

HttpResponse<String> response = client.send(
    request, HttpResponse.BodyHandlers.ofString());

System.out.println(response.statusCode());
System.out.println(response.body());
```

```java
// Async
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
    .thenApply(HttpResponse::body)
    .thenAccept(System.out::println);
```

**Interview Point:** HttpClient supports HTTP/2, async, connection pooling. Standard since Java 11.

</details>

---

# 8. Difference from HttpURLConnection?

<details>
<summary>Show Answer</summary>

**Answer:**

| | HttpURLConnection | HttpClient (11+) |
|---|-------------------|------------------|
| API | Clunky, old | Clean builder API |
| HTTP/2 | No | Yes |
| Async | Manual threads | `sendAsync()` built-in |
| Connection pool | Manual | Built-in |
| WebSocket | No | Supported |

**Interview Point:** HttpClient = modern replacement. HTTP/2, async, better API.

</details>

## Collections

---

# 9. toArray(IntFunction)?

<details>
<summary>Show Answer</summary>

**Answer:**

`Collection.toArray(IntFunction)` — cleaner array creation from collection.

```java
List<String> list = List.of("a", "b", "c");

// Old
String[] arr = list.toArray(new String[0]);

// Java 11
String[] arr = list.toArray(String[]::new);
```

**Interview Point:** toArray(String[]::new) — generator pattern, cleaner than new String[0].

</details>

---

# 10. var in lambda?

<details>
<summary>Show Answer</summary>

**Answer:**

Java 11 allows **`var` in lambda parameters** (with `-parameters` compiler flag for reflection).

```java
// Java 11 — var in lambda (both params must use var if one uses)
BiFunction<String, String, Integer> f =
    (var a, var b) -> a.length() + b.length();
```

Limited use — mainly for annotations on lambda params.

**Interview Point:** var in lambda = Java 11. Rare in practice. Local var was Java 10.

</details>
