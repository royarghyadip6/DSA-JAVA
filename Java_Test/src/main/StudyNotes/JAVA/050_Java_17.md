# 2. Sealed Classes?

<details>
<summary>Show Answer</summary>

**Answer:**

**Sealed class** restricts which classes can **extend** it — explicit allowed subclasses only.

```java
public sealed class Shape permits Circle, Rectangle, Triangle {
    // only Circle, Rectangle, Triangle can extend Shape
}

final class Circle extends Shape { }
final class Rectangle extends Shape { }
// class Pentagon extends Shape { } // compile error
```

Subclasses must be: `final`, `sealed`, or `non-sealed`.

**Interview Point:** sealed + permits = controlled inheritance. Better than open extends for domain models.

</details>

# 3. Records?

<details>
<summary>Show Answer</summary>

**Answer:**

**Record** = immutable data carrier — compiler generates constructor, getters, equals, hashCode, toString.

```java
public record Employee(Long id, String name, double salary) { }

Employee emp = new Employee(1L, "John", 50000);
emp.name();    // accessor — not getName()
emp.id();
```

```text
Auto-generated: constructor, equals, hashCode, toString, getters
Cannot extend other classes (implicitly extends Record)
Can implement interfaces
```

**Interview Point:** record = immutable DTO. name() not getName(). Compact syntax for data classes.

</details>

# 4. Pattern Matching?

<details>
<summary>Show Answer</summary>

**Answer:**

**Pattern matching** simplifies type checks and casts — Java 16+ `instanceof`, Java 21+ switch patterns.

```java
// Java 16+ instanceof pattern
if (obj instanceof String s) {
    System.out.println(s.length()); // s already cast
}

// Java 17 preview / 21 finalized switch patterns
switch (shape) {
    case Circle c -> System.out.println(c.radius());
    case Rectangle r -> System.out.println(r.width() * r.height());
    default -> throw new IllegalArgumentException();
}
```

**Interview Point:** instanceof pattern eliminates manual cast. Sealed + switch = exhaustive type handling.

</details>

# 5. Record vs POJO?

<details>
<summary>Show Answer</summary>

**Answer:**

| | Record | POJO |
|---|--------|------|
| Immutability | Immutable by default | Mutable with setters |
| Code | One line + optional methods | Fields, ctor, getters, equals, hashCode |
| Getters | `name()` | `getName()` |
| Inheritance | Cannot extend classes | Can extend |
| JPA entity | Poor fit (immutable, no lazy) | Traditional entity |
| DTO/API response | ✅ Ideal | Works but verbose |

```java
// Record — 1 line
public record UserDto(String name, String email) { }

// POJO — 50+ lines for same
```

**Interview Point:** Record for DTOs, events, value objects. POJO/entity for JPA mutable entities.

</details>

# 6. Record vs Lombok?

<details>
<summary>Show Answer</summary>

**Answer:**

| | Record | Lombok @Data/@Value |
|---|--------|---------------------|
| Language feature | Java keyword | Compile-time codegen |
| Immutable | Always | @Value for immutable |
| Reflection | Works natively | Generated methods |
| Custom equals | Manual override | Manual |
| IDE support | Native | Needs Lombok plugin |

```java
@Value // Lombok immutable
class UserLombok {
    String name;
    String email;
}

public record UserRecord(String name, String email) { }
```

**Interview Point:** Prefer record for simple DTOs — no Lombok dependency. Lombok when you need builders on mutable classes.

</details>

# 7. Sealed Class use cases?

<details>
<summary>Show Answer</summary>

**Answer:**

| Use Case | Why Sealed |
|----------|------------|
| **Domain model** | Fixed set of types (Payment: Card, UPI, Wallet) |
| **AST nodes** | Expression types in compiler/parser |
| **State machine** | Order states — exhaustive switch |
| **API responses** | Success/Error variants |
| **With records** | sealed interface + record implementations |

```java
public sealed interface Result permits Success, Failure { }
public record Success(String data) implements Result { }
public record Failure(String error) implements Result { }
```

**Interview Point:** Sealed when closed set of subtypes. Enables exhaustive pattern matching in switch.

</details>

# 8. Permitted subclasses?

<details>
<summary>Show Answer</summary>

**Answer:**

`permits` clause lists **allowed direct subclasses** of sealed class/interface.

```java
public sealed class Animal permits Dog, Cat { }

final class Dog extends Animal { }   // must be in permits list
final class Cat extends Animal { }   // must be in permits list
```

Rules for permitted subclasses:
```text
final     — cannot be extended further
sealed    — can have own permits
non-sealed — open for further extension
```

All direct subclasses must be listed in `permits`.

**Interview Point:** permits = whitelist of subclasses. Compiler enforces. Subclass must be final/sealed/non-sealed.

</details>
